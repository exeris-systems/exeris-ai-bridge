# ADR-095 — exeris-tooling's stable diagnostic identifiers (link stub)

**Authoritative copy:** [`exeris-tooling/docs/adr/ADR-095-stable-diagnostic-identifiers.md`](https://github.com/exeris-systems/exeris-tooling/blob/main/docs/adr/ADR-095-stable-diagnostic-identifiers.md)

ADR-095 is a **cross-repo** decision owned by `exeris-tooling`. From exeris-tooling 0.9.0 on, every
message the annotation processor prints, every failure or warning an `exeris:*` goal raises, and every
warning the code-generation pipeline logs carries an identifier between the `[Exeris]` prefix and the
text:

```
[Exeris] EXT-PROC-1101: @ExerisDomain.tenantScoped is deprecated for removal in SDK 1.0.0; …
[ERROR] Failed to execute goal …: [Exeris] EXT-PLUG-2001: Refusing to wipe the committed generated tree: …
```

The full table, with what each identifier means and what to do about it, is
[`exeris-tooling/docs/diagnostics.md`](https://github.com/exeris-systems/exeris-tooling/blob/main/docs/diagnostics.md).

## Why this stub exists

This repository is the consumer the decision names (obligation 9): `build-explain_diagnostic` is to
look a pasted diagnostic up by identifier first, and keep its text anchors only for output from
tooling releases before 0.9.0. Its catalogue still matches on text today; every existing anchor keeps
matching, because the identifier is inserted before the text, not in place of it. What binds the
bridge:

- **Match the identifier, not the text.** The regular expression `\[Exeris\] (EXT-[A-Z]+-\d{4}): `
  finds one anywhere in a line; Maven puts `[ERROR] Failed to execute goal …:` before it, so an
  anchor at the start of a line does not hold. The text after the identifier may be reworded in any
  release.
- **An identifier is never renumbered or reused.** A retired identifier stays listed as retired in
  `docs/diagnostics.md`; a severity change keeps the identifier. A catalogue entry keyed on an
  identifier therefore stays correct across tooling releases.
- **The bridge owns its catalogue and its slugs.** Each slug maps to one identifier, and several slugs
  may share one (the three `caps/*` graph slugs are all `EXT-PLUG-2201`). The ADR records the mapping
  for the catalogue as it stood when the decision was taken.
- **`EXT-` is not the kernel's `EX-`.** Kernel error codes (`EX-<DOMAIN>-<NNNN>`) are a separate
  namespace; a lookup keyed on one never matches the other.

## When to consult ADR-095

- Adding or changing a catalogue entry in `build-explain_diagnostic`.
- A tooling release that adds, retires or re-severities an identifier.
- Any change that parses Exeris build output.
