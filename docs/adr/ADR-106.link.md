# ADR-106 — the pre-construction brief contract (link stub)

**Authoritative copy:** [`exeris-sdk/docs/adr/ADR-106-pre-construction-brief-contract.md`](https://github.com/exeris-systems/exeris-sdk/blob/main/docs/adr/ADR-106-pre-construction-brief-contract.md)

ADR-106 is a **cross-repo** decision owned by `exeris-sdk`. A pre-construction brief,
`docs/briefs/<area>.brief.yaml` in an application project, is defined by records in
`exeris-sdk-source-model` under `eu.exeris.sdk.brief`. `BriefSchemaProcessor` emits
`META-INF/exeris/brief-schema.json` from them into that module's jar: a closed JSON Schema in which
no structure `DomainMetadata` carries has a slot. The contract ships in SDK 0.13.0 as
`briefSchemaFormat` 1.

## Why this stub exists

This repository is the consumer the decision names. Under the ADR-025 2026-10-27 amendment the
bridge serves the brief schema as an `sdk:*` resource, validates project briefs with
`build-validate_brief`, and ships the `discover-requirements` prompt that ends in that validation.
None of the three is registered until a released SDK carries the schema. What binds the bridge:

- **Vendor the schema from the released jar, pinned to `briefSchemaFormat`.** Take it at pack time
  from `exeris-sdk-source-model`, as the AST schema is taken. Refuse an unknown format number; it moves
  only when a brief valid under the previous number would stop validating.
- **Readiness is the ADR's function, not the bridge's.** A brief is ready when it is valid against
  the schema and no blocking question is `open`. An absent or empty brief is never ready. The bridge
  restates no other rule.
- **EARS criteria are checked by structure, never by text.** The fields required per `kind` are in
  the schema; no response or meaning is inspected.
- **Resolving `fulfilledBy` is the caller's job.** The SDK resolves no reference. The bridge resolves
  each against the project's emitted `DomainMetadata` by its kind, and reports references it cannot
  check as unchecked, not failed.
- **Validate against the project's pinned SDK.** A brief whose `briefSchema` is newer than the SDK
  the project pins is reported as skew and not validated.

## When to consult ADR-106

- Adding or changing `build-validate_brief`, the brief schema resource or the
  `discover-requirements` prompt.
- An SDK release that moves `briefSchemaFormat` or changes a brief property.
- Any change to how `author-domain` treats a brief for its area.
