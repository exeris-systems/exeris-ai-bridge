# ADR-033 — `KernelDiagnostics` SPI — Read-Only Runtime Introspection for Agent and CLI Adapters (link stub)

**Authoritative copy:** [`exeris-kernel/docs/adr/ADR-033-kernel-diagnostics-spi.md`](https://github.com/exeris-systems/exeris-kernel/blob/main/docs/adr/ADR-033-kernel-diagnostics-spi.md)

ADR-033 is a **cross-repo** decision owned by `exeris-kernel`. It defines the public, read-only SPI surface (`eu.exeris.kernel.spi.diagnostics.KernelDiagnostics`) that this repository consumes through its `kernel:*` MCP tool family.

## Why this stub exists

`exeris-ai-bridge` 0.4.0 was explicitly blocked on a `KernelDiagnostics` SPI per `ROADMAP.md` §0.4.0 and ADR-025 §Engineering Protocol item 2. ADR-033 is the contract that unblocks it: the three `kernel:*` tools (`kernel:list_providers`, `kernel:get_bootstrap_dag`, `kernel:describe_subsystem`) map onto the corresponding SPI methods (`listProviders`, `getBootstrapDag`, `describeSubsystem`).

**Cap-blind correction (2026-06-17):** the family does **not** include `kernel:list_capabilities`. The open kernel is cap-blind (ADR-024 revised obligation 9), so capability composition is not a kernel surface; the kernel-side `KernelDiagnostics.listCapabilities()` / `CompositionSnapshot` / `CapabilityDescriptor` are being removed in lockstep (ADR-033 revision, owned by `exeris-kernel`). See ADR-025 §"`kernel:*` Is Cap-Blind". `getJvmErgonomics()` exists on the SPI but is not yet surfaced as a tool.
