# ADR-086 — the AI execution layer, bounded to observation before routing (link stub)

**Authoritative copy:** [`exeris-docs/adr/ADR-086-bound-the-ai-execution-layer-to-observation-before-routing.md`](https://github.com/exeris-systems/exeris-docs/blob/main/adr/ADR-086-bound-the-ai-execution-layer-to-observation-before-routing.md)

ADR-086 is a **cross-repo** decision owned by `exeris-docs`. It places the AI execution layer in its
own repository, `exeris-ai-execution`, and fixes what that layer may do before it may decide: it
observes and does not route (§B.5), and the seam runs from `exeris-agents` to it and never the other
way (§A.2).

## Why this stub exists

§A.3 names this repository: `exeris-ai-bridge` is a **context adapter** to the execution layer, later,
under [ADR-025](ADR-025-ai-agent-bridge.md) — **never its host**. The bridge's mission runs from Exeris
surfaces *to* agents; the execution layer runs the other way. A pull request that adds capture, a
dataset or an oracle to the bridge is out of bounds.

The constraint is easy to cross by accident, because the bridge already sits between agents and the
ecosystem and every tool call passes through it. Recording those calls, keeping them as rows, or
judging their outcome would each make the bridge a host of the layer ADR-086 places elsewhere.
The adapter's shape is not decided by ADR-086: it arrives under ADR-025, which means read-only and
through an amendment there before any tool lands here.

Engineering Protocol 6 of the ADR owes this stub; it is paid here.

## When to consult ADR-086

- Any proposal that the bridge log, persist or score agent tool calls or their results.
- Any proposal for a tool family that touches `exeris-ai-execution` in either direction.
- Any ADR-025 amendment touching the bridge's direction of responsibility.
