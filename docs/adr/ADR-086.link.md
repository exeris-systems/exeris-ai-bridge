# ADR-086 — Bound the AI Execution Layer to Observation Before Routing (link stub)

**Authoritative copy:** [`exeris-docs/adr/ADR-086-bound-the-ai-execution-layer-to-observation-before-routing.md`](https://github.com/exeris-systems/exeris-docs/blob/main/adr/ADR-086-bound-the-ai-execution-layer-to-observation-before-routing.md)

ADR-086 is a **cross-repo** decision owned by `exeris-docs`. It fixes the boundary of the AI execution / workload-intelligence layer, which runs in `exeris-ai-execution`, and states what that layer may observe before it may decide anything about routing.

## Why this stub exists

ADR-086 §A.3 binds this repository to one role: `exeris-ai-bridge` is a **context adapter** to the execution layer, later, under ADR-025 — never its host. The bridge's mission runs from Exeris surfaces *to* agents; the execution layer runs the other way. A change that adds capture, a dataset or an oracle to this repository is out of bounds, whatever its size.

This repository therefore does not hold:

- capture of agent runs or telemetry, in any form;
- a dataset built from those runs;
- an oracle that judges their outcomes.

Those belong to `exeris-ai-execution`. The bridge's `docs:*`, `lsp:*`, `kernel:*`, `build:*`, `caps:*` and `bridge:*` families stay read-only and keep serving agents, as ADR-025 requires.

## When to consult ADR-086

- Proposing any new capture, logging sink, dataset or evaluation inside this repository. §A.3 says no; the proposal belongs in `exeris-ai-execution`.
- Reviewing a change that sends run data out of the bridge, or that reads run data into it.
- Changing how this repository is described to the execution layer or to the agent bundle. The founding boundary is [`ADR-025`](ADR-025-ai-agent-bridge.md); ADR-086 §A.3 follows from it.
