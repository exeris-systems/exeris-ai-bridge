# ADR-086 — Bound the AI Execution Layer to Observation Before Routing (link stub)

**Authoritative copy:** [`exeris-docs/adr/ADR-086-bound-the-ai-execution-layer-to-observation-before-routing.md`](https://github.com/exeris-systems/exeris-docs/blob/main/adr/ADR-086-bound-the-ai-execution-layer-to-observation-before-routing.md)

ADR-086 is a **platform-scope** decision owned by `exeris-docs`. It bounds the AI execution layer to observation before it may route, and its §A.3 places this repository against that layer.

## Why this stub exists

§A.3 gives `exeris-ai-bridge` one role and refuses it another. The bridge is a **context adapter** to the execution layer, later, under ADR-025 — and **never its host**. The direction is the reason: this repository's mission runs from Exeris surfaces *to* agents, and the execution layer runs the other way, from what a run did back to whoever reads it. A pull request that adds capture, a dataset or an oracle here is out of bounds; `exeris-ai-execution` owns all three under §A.1.

So the clause is a boundary this repository is read against rather than a dependency it takes on. Nothing here consumes the execution layer, and §A.3 holds whether or not the adapter is ever built. The question it answers is the one a reader reaches on their own: the `bridge:*` family already reports this server's own state, so why may the next tool not report what a session did with it? Because that tool would be capture, and capture is hosted in the other repository.

Engineering Protocol 6 of the ADR owes this stub; it is paid here.

## When to consult ADR-086

- Any proposal to record, store, aggregate or score what an agent session did — §A.3 puts all of it outside this repository, whatever its size.
- Any new tool family, or any extension of the two-tool `bridge:*` family, whose output is about runs rather than about an Exeris surface (see ADR-025 §Concrete obligations and [`CLAUDE.md` §"Tool family scope"](../../CLAUDE.md)).
- Any dependency proposed on `exeris-ai-execution`, or on the telemetry sink contract §A.2 places in `exeris-agents` — the sink's direction is fixed, and this repository is on neither end of it.
- Any future work on the context adapter §A.3 permits: it arrives under ADR-025, which means an ADR-025 amendment first, exactly as a new tool family does.
